# T5: Algorithm B, TT-native DIS-TT (`src/dis_tt/native.py`)

## Plan
1. `tt.right_orthogonalize` each snapshot once; total = sum ||core_1||_F^2; Phi_tau = [[1]].
2. Bond k: B_tau = einsum(Phi_tau, core_k) reshaped to rows (alpha_{k-1}, i_k), alpha slowest;
   stream H_k = sum_tau B_tau B_tau^T ((r_{k-1} n_k)^2 memory), `np.linalg.eigh`, clip >= 0,
   `linalg.select_rank` with the same rules as Algorithm A (eps / rmax / ranks / D).
3. G_k = V[:, :r_k]; Phi_tau <- G_k^T B_tau. Never call `tt.to_dense` / `tt.block_to_dense`.
4. Extras (`tests/test_native_extra.py`): mixed snapshot TT ranks, n_k != 2, D = d-1, T = 1,
   rank caps; then measure runtime vs T (3 sizes) and vs QTT depth (6, 8, 10).

## Design choices
- Same argument semantics as Algorithm A (`D` defaults to len(ranks) or d; ranks override
  eps/rmax; eps=None -> full numerical rank via `select_rank(delta2=None)`).
- H_k is formed explicitly ((r_{k-1} n_k)^2) and solved with `np.linalg.eigh` on its symmetric
  part; eigenvalues clipped at 0; spectra are complete (`spectra_complete` all True).
  There is no randomized backend in Algorithm B (signature has none).
- B_tau for the current bond are kept for all tau (O(T r n R) memory, inside the stated
  O(T d n R^2) budget) so Phi_tau = G_k^T B_tau needs no recontraction.
- `total` = sum_tau ||core_1||_F^2 after right-orthogonalisation.
- ValueError for empty list, mismatched mode sizes, bad D / len(ranks).
- Only `tt.right_orthogonalize` is called from the tt module (accessed as `tt.<name>`).

## Timings (only `dis_tt_native` timed, best of 3; script: smooth 8-mode family, TT-SVD eps 1e-10)
vs T (d = 8, eps = 1e-3, max snapshot TT rank R = 12):
  T=100 39.5 ms, T=200 74.0 ms (x1.87), T=400 152.1 ms (x2.06)  -> linear in T.
vs QTT depth (T = 200, eps = 1e-3):
  d=6  (R=8)  ranks (2,4,8,15,14,8)                    50.7 ms
  d=8  (R=12) ranks (2,4,8,16,17,15,13,8)              74.2 ms (x1.46)
  d=10 (R=12) ranks (2,4,8,16,18,15,13,13,12,8)        96.8 ms (x1.30)
  Bond count ratio 6:8:10 = 1:1.33:1.67, measured 1:1.46:1.91: roughly linear in d, the excess
  tracks the growth of R and r with depth (cost has R^3 and r^2 n^2 R terms).
Observation: at these sizes dense Algorithm A is 15-70x faster (0.7 / 1.4 / 5.2 ms) because
Algorithm B is a Python loop over T snapshots per bond. The dense cost grows as d_Y = 2^d
(x2.0, x3.7 here) while native grows ~linearly in d, so B wins only at much larger depth or
when densifying is impossible. Not optimised further (batching equal-rank snapshots is a
possible follow-up).
